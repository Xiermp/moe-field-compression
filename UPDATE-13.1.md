# UPDATE-13.1 — build 13.1 (2026-09-08): T2-POLISH — два фикса взрыва фита + polish-профиль для bank-init

Что случилось в прогоне 2026-09-08 (stage 5, `muon`, svd-init t2_k64):

- step-0 mse **0.005–0.12** — инит уже почти сошёлся (capture gu ~99%, dn ~40–80%);
- к шагу ~100 mse **10³–10⁶** — все 23 блока разошлись, `best state restored`;
- `best-state re-eval: mse 120.4` при step-0 `0.00457` — restored-состояние в
  **тысячи раз хуже** инита, которым его объявили;
- артефакт: **KL 2.288 бит/ток, ppl 168.80 (+322%)**, probe A плоский ~2.1–3.1
  на всех позициях — глобально сломанная репрезентация.

## Причина 1 — off-by-one в best-state машине (главное)

В `fit_field_module` снапшот параметров снимался **ПОСЛЕ** `opt.step()`, а его
скор (ema лосса) считался **ДО** шага:

```python
loss.backward(); opt.step()          # параметры уже дёрнулись
last = loss.item()                   # лосс ДО шага
...
best_score, best_state = ema, _snapshot()   # снапшот ПОСЛЕ шага!
```

Пара (score, state) описывает **разные веса**. Пока фит шёл из слепого инита
(mse 0.1–1, улучшение монотонное), лаг в один шаг был невидим. С bank-инитом,
который уже оптимален на шаге 0, «лучшее состояние» — это ВСЕГДА «инит + один
пинок оптимизатора»: score 0.00457, а в снапшоте — уже пнувшиеся веса. Bail по
дивергенции восстанавливал именно их → re-eval 120 → **в fit_blk уехали пнутые
параметры** → артефакт KL 2.288. Это и есть «подгонка 0»: фит не добавил ничего,
кроме разрушения.

Фикс: весь решающий блок (ema / best / bail / early-stop) выполняется **до**
`opt.step()`; снапшот — пред-шаговые параметры; при bail шаг не тратится.

## Причина 2 — профиль оптимизатора от слепого инита

Muon делит обновление через Newton-Schulz: сингулярные значения апдейта
выравниваются в ~1, шаг имеет **полную мощность независимо от величины
градиента** (нормировка на норму). Adam на C*/w* — то же самое мягче: шаг
~lr на координату вне зависимости от градиента. При mse 0.005 градиенты на
2–3 порядка меньше, чем при слепом старте, а lr=2e-3 прежний → первые же шаги
выбрасывают сошедшуюся точку из узкой долины (пик ema ~1.5e5 между шагами
1–100 — траектория болталась на уровне 10⁵–10⁶). Probe это же подтвердил:
«fp32 596 ms, mse 3409/423» — сам честный probe разогнал инит за 4 шага
(он восстанавливает параметры, это косметика, но дым тот же).

Разбор из ревью верен в рецептах (уронить lr ×20–50, adamw без Muon,
разогрев, морфить базу); уточнение по механике: «тэта-кубический резонанс
ΔU·ΔG·ΔV» реален, но вторичен — главную работу делают нормированные шаги
Muon/Adam в точке, где градиент ≈ 0. Заморозка U/V — самый сильный рычаг:
задача в ядрах становится (почти) выпуклой, взрываться нечему.

## Что изменено

### 1. `hf_field_transform.py`

- **fit_field_module**: решающий блок перенесён ДО `opt.step()` (фикс 1);
  новый параметр `train="all"|"core"` — core морозит все факторы `U*/V*`
  (те самые NS-кандидаты), обучаются только ядра `C*`, центроиды `w*` и,
  если joint, роутер;
- **init baseline печатается всегда** (в т.ч. с `--skip-fit-guard`):
  `init baseline (eval8): mse ...` — с bank-инитом это число, на котором
  стоит весь прогон;
- **гвард «mse got WORSE» получил допуск 5%**: `first` и post-restore `last`
  — два независимых eval8-замера; в polish-режиме (last ≈ first) строгое
  `>` превращало гвард в монетку — Raised на одинаковых весах;
- **polish_router_module**: тот же фикс пред-шагового снапшота.

### 2. `hf_pipeline.py`

- новый флаг **`--fit-train {all,core}`** (дефолт: `core` при
  `--bank-init t2`, иначе `all`), прокинут в оба вызова фита;
- **polish-профиль для t2 по умолчанию**: если пользователь НЕ зафиксировал
  `--fit-method/--fit-lr`, t2-прогон стартует как
  `method=adamw lr=1e-4 warmup=20 train=core`
  (строка `t2 polish profile: ...` в логе); пресет/явные флаги главнее;
- `fit_sig` несёт `fit_train` → старые t2 fit-файлы (с пнутыми параметрами)
  автоматически переписываются одним ре-фитом; `init_svd_blk*`, кэш ковараций
  и pair pool **остаются валидными** — stage 4 переиспользуется как есть
  («0 rebuilt, 23 reused»), пересбора за 347 s не будет;
- профиль/отчёт печатают `train=...`.

## Как перезапустить

Вариант А — всё по новым дефолтам:

    python hf_pipeline.py <ваши модельные флаги> --bank-init t2 --rank 64 \
        --stages fit,save,verify

Вариант Б — явно, как в ревью (+ заморозка базы):

    python hf_pipeline.py <ваши модельные флаги> --bank-init t2 --rank 64 \
        --fit-method adamw --fit-lr 5e-5 --fit-steps 100 --fit-early-stop 20 \
        --fit-lr-warmup 20 --fit-train core --stages fit,save,verify

`--skip-fit-guard` больше не нужен — убери его: с фиксом 1 худший исход
блока — «barely moved, shipping the best state» (= чистый инит).

## Как читать лог

1. `init baseline (eval8): mse 0.00x` — инит хорош ещё до фита;
2. `step 0: mse ...` ≈ baseline; дальше либо медленное улучшение
   (полировка работает), либо `loss diverged ... best state restored` +
   `best-state re-eval: mse ...` **равный** baseline (теперь restored =
   честный инит) + `FIT GUARD: mse barely moved ... (no gain, no harm)`;
3. гвард: `guard: mse X -> Y (Z% below ...)` — X ≈ Y в polish-режиме это
   норма, а не провал: инит уже выучил то, что раньше учил фит.

## Если KL после этого всё ещё плохой

Тогда пнутые fit-файлы были не причиной, и подозрение переезжает на путь
«модуль → артефакт» (write/reload, dense-core payload, bf16-шафлы).
Проверка одной строкой: в логе нового прогона `init baseline (eval8)` по
блокам малый (0.00x), а artifact KL большой → несоответствие между
fit-модулем и записанным артефактом — это уже UPDATE-13.2 (сравнить
fit-pool mse модуля vs mse перезагруженного артефакта на тех же парах).
