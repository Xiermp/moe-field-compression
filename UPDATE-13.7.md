Дата: 2026-09-13. Базовый код: 13.6.4-fit-fresh (штампы 2026-09-11.1).
Новые файлы: **test_update137_dense.py**. Изменены: hf_field_transform.py

## 1. Мотивация - zero-shot аудит первой инициализации

Вопрос пользователя: «цель zero shot - максимальное качество без настройки.
Правильно ли мы делаем первую инициализацию?» Два стенда, один протокол:
init -> метрики СРАЗУ (без stage-5), калибровка и оценка на непересекающихся
сегментах.

1. **Игрушка** (TinyMoE, base ppl 8.12): на том же joint-v2 сабспейсе
   ПЛОТНОЕ ядро `C_e = U^T dW_e V` удваивает capture (r=32: 0.585/0.563
   против diag 0.149/0.194) и вдвое улучшает KL zero-shot (0.630 против
   1.310 бит/токен). Лучший zero-shot init даёт лучший итог и ПОСЛЕ фита
   при равном бюджете (final KL 0.010 против 0.020).
2. **Микро-реальная MoE** (google/switch-base-8: энкодер T5-base, 6 sparse
   слоёв x 8 экспертов, relu FFN, top-1 роутинг; коварации и активационные
   метрики на РЕАЛЬНОМ роутинге tinyshakespeare): пакетный дефолт
   diag-jointv2 - худший из нетривиальных на обеих сторонах и всех ранках.
   dense-jointv2 (те же U,V + полное ядро) стабильно лучше diag ВЕЗДЕ:
   активационная ошибка -5.8..-11.2% (up-сторона), -38.2..-54.4%
   (down-сторона), ранги 8..64, 2 seed, макро-средние по 6 слоям.
3. Весовое пространство: capture у ЛЮБОГО общего базиса крошечный
   (0.9-4.4% против 10-27% у per-expert SVD) - дельты реальных экспертов не
   низкоранговые; при этом активационная ошибка падает на 35-66% =>
   решения по init принимать по АКТИВАЦИОННОЙ метрике.

Диагноз: ДИАГОНАЛЬ была узким местом zero-shot init - она выбрасывает все
кросс-члены общего базиса, которые и несут энергию дельт.

## 2. Что добавлено

**core="dense"** в `expert_basis_init` (флаг `--bank-init dense`): те же
joint-v2 базисы (U, V - бит-в-бит те же: ядро вычисляется из ТОГО ЖЕ стэша
`B`, машинерия базиса не трогается), но координаты - ПОЛНОЕ ядро
`C_e = U_B^T B_e V` формы (E, r, r) вместо диагонали (E, r). Это
Tucker-2-ядро, которое контейнер несёт с UPDATE-13 (`apply_core`), так что
фит и артефакт не меняются. Банк 2 остаётся ДИАГОНАЛЬНЫМ (правило
контейнера), но его невязка считается от ПЛОТНОЙ реконструкции банка 1.

- Стоимость: +r^2 на эксперта (r=32, 64 эксперта: ~131K float на блок
  против мегабайт экспертов) - сжатие x60 не тронуто; цена init-прохода
  НЕ выросла (K и раньше materialизовался для capture_proj).
- Данные не нужны: ядро строится из стэша дельт весов, калибровочный пул
  не участвует.
- Штампы: `svd_ver` = "joint-v2-dense" (+ "+b2"); `capture_metric` =
  "full core (13.7)"; capture == capture_proj по построению. Новый хелпер
  `svd_init_ver(core, banks)` - единственная точка, где пайплайн и init
  считают сигнатуру (stamp и проверка файла не могут разойтись).
- Кэши: fit в ОТДЕЛЬНОМ каталоге `fit_r<rank>dense` (как t2/du*) - старые
  фиты не тронуты. Дефолт `--bank-init svd` бит-в-бит 13.6.x: те же
  значения диагонали (batched `torch.diagonal` от того же K), тот же
  штамп "joint-v2", старые init-файлы остаются валидными.
- Профиль фита: t2-polish (train=core, adamw 1e-4) на dense НЕ включается
  - dense-init не сходившийся, ему нужен полный дефолтный фит
  (train=all, muon/adam).

## 3. Как запускать (zero-shot-first рецепт)

    # полная труба с плотным ядром: init -> fit -> save -> verify
    python hf_pipeline.py <ваши модельные флаги> --bank-init dense \
        --rank 32 --stages fit,save,verify

    # только пересобрать init-файлы под новый режим (пул переиспользуется)
    python hf_pipeline.py <ваши модельные флаги> --bank-init dense \
        --refresh-init

    # zero-shot аудит init без фита (шаг-0 mse по блокам, модель не нужна)
    python init_audit.py --pool results/cache_... --fit-dir results/.../fit_r32dense \
        --rank 32 --blocks 0,10,20

Ожидания по прогону: в баннере stage-4 - "svd init (joint-v2-dense,
joint-aligned, dense core): ... capture", в stage-5 fit_sig несёт
svd_ver "joint-v2-dense", артефакт - cfg.field.core = "dense".

## 5. Связь с внешним разбором (20 пунктов)

- п.2 (diag(c) жёсткая): дешёвый первый шаг без смены архитектуры -
  плотное ядро и есть A(c) = c при фиксированном сабспейсе; блочные
  A(c)/гиперсети остаются следующим рычагом.
- п.9 (масштабы U/V/C): масштабы координат теперь ЗАДАЮТСЯ ядром (полная
  проекция), а не диагональю - источник систематического недобор-а исчез.
- п.1 (ёмкость): реальный потолок общего базиса измерен на реальной модели
  (весовой capture 0.9-4.4% против 10-27% per-expert) - аргумент за
  пер-экспертную ёмкость (du-банк 13.5, банк 2) подтверждён независимо.

Не закрыто этим апдейтом (сознательно): zero-shot save-путь артефакта
(stage 6 пока требует fit_blk*.pt; step-0 качество доступно через
init_audit.py и стенды scripts/zeroshot_*_eval.py), регуляризация
разнообразия C (п.19), температура роутера (п.18).
